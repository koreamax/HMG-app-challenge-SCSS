# 적재적소 디자인 명세

v1 · 2026-11-13, **겉면 v2 · 2026-11-14 (§7)**. 팀 GitHub 화면(`base/display/twin/web/src/components/ui/twin-page.css` · `twin-controls.tsx` · `twin-page.tsx`)을 키운다. **내비 판**: Pleos Connect 가로 1920×720 · 1920×1080, 낮 · 밤. **폰 판**: Android 세로 390×844, 낮. 두 판은 운송장 하나를 클라우드로 같이 쓴다.

치수는 앱 창 px. 창 높이 900 이상이면 1080 값. 창이 작아지면(AAOS 막대) 3D 무대와 주행 글 영역만 줄인다.

## 1. 평가

- **지킬 것**: 판정 띠(남색 표지 + 색 줄) → 남색 3D 띠 → 아래 칸(위 색 줄)의 뼈대. 흰 판, 모서리 0, 그림자 없음, 1px 선, Pretendard 700/300, 파랑은 누를 것에만, 흰 바탕 상태 글자는 어두운 `-t`. 판정이 먼저 읽히고 차분하다. 〔v2: '흰 판, 모서리 0, 그림자 없음, 1px 선, 700/300' 과 색 줄은 §7 이 대신한다. 뼈대 · 파랑 규칙 · 상태 글자 규칙은 그대로〕
- **차에 맞게**: 800×480 값(글자 11~13, 단추 52)은 1920 폭에서 작다. 글자 24 · 터치 80 이상, 2.67:1 이라 오른쪽 단을 더한다. 밤 모드는 GitHub 남색 면에서 만든다.
- **덜어낼 것**: 노랑, 깜박이는 표지, 끝없는 꼬리표 퍼짐, 색 범례, 녹화 · Hz 칸. 숨쉬는 테두리는 정차 중 빨강만, 주행 중엔 고정. 깜박임 대신 표지 모양을 넷으로.
- **폰**: 가로 키오스크를 세로로(위 앱 바, 아래 탭, 칸 2×2, 터치 48). 토큰은 내비 낮과 같다.
- **Night Navy 의 잘못**: 둥근 모서리 · 그라데이션 · 빛 번짐 · 물결 · 반짝 테두리 · 흐림으로 흔한 다크 템플릿이 됐다. 주행 색은 168 px 점과 옅은 빛뿐이라 약했고 글은 두 줄이었다. 하늘색이 다섯째 색이 됐고, 13 px 회색 글이 많았고, 낮 모드가 없었다.
- **살릴 것**: 화면 묶음, 주행 규칙, 벨트 꼬리표 · 순서 배지 · 출발 때 자리 점선, '밀렸나요?' 물음, 신고 번호.

## 4. 화면 배치 (x,y · 폭×높이)

### 4.1 내비 · 정차 3D 확인

```

y112  [rail][stage ..........................][right col]    h480 / 792
y592  [limit][cargo][belts][wall]      (right col to bottom) h128 / 160
```

| 영역 | 1920×720 | 1920×1080 |
|---|---|---|
| 판정 띠 | 0,0 · 1920×112 | 0,0 · 1920×128 |
| 왼 막대 | 0,112 · 120×480 | 0,128 · 136×792 |
| 3D 무대 | 120,112 · 1320×480 | 136,128 · 1264×792 |

- **띠**: '밀릴 수 있음' · '바 하나 더 거세요' / '또는 짐을 앞벽에 붙여 실으세요' · 메타 운송장 번호 / '정차 중 · ■ 키트'. 할 일 단추는 `verdict.kind` 로: `slide` '벨트 수 고치기'(상차 시트) · `tip` '넘어짐 봤어요'(눈으로 확인 '넘어짐' 체크) · `none` '상차 정보 넣기' · `ok` 없음.

### 7.1 방향

- **회청색 바탕 위 회청색 카드 (흰 판 없음, §7.6)**: 앱 바탕은 회청색(`--bg`), 내용은 한 단계 밝은 회청색 카드(`--canvas`)에 묶는다. 묶음은 선이 아니라 색 차이와 간격(내비 12 · 폰 8 ~ 16)으로 나눈다. 선은 카드 안 줄 사이에만, 줄 안쪽 여백만큼 들여서.
- **센 곳은 하나**: 판정 카드(표지 + 판정 말 + 할 일 + 주 단추)가 화면에서 가장 세다. 나머지(칸 · 눈으로 확인 · 메타)는 한 단계 조용하게(이름 600, 보조 400, 회색).
- **남색 3D 무대가 닻**: 낮 화면에서 가장 어두운 면은 무대 하나. 표지는 계기판 경고등처럼 둥근 남색 칸 + 상태 모양(색 줄은 없앴다).
- **파랑 면은 주 단추만**: 화면에 파랑 면은 하나. 고른 것(보기 · 짐 종류 · 무게 · 거르기)은 옅은 파랑 면 + 파랑 테두리 + 파랑 글. 버금 단추는 회색 면, 조용한 단추는 면 없음.
- **꾸미지 않는다**: 그라데이션 · 빛 번짐 · 유리 효과 없음. 그림자는 떠 있는 것(자세히 · 알림 · 시트)에만. 글꼴은 Pretendard 하나(`'Pretendard', sans-serif`).

### 7.4 부품 규칙

- **단추**: 주 = 파랑 면 + 흰 글 700, 누름 `--primary-active`, 화면에 하나. 버금 = `--surface-strong` 면 + `--ink` 600, 누름 `--surface-press`, 테두리 없음. 조용한 = 면 없음(막대의 기록 · 설정, 돌아가기), 누름 `--surface-strong`. 위험 = `--bad-soft` 면 + `--bad-t` 글. 꺼짐 = `--surface-strong`(주) · `--surface-soft`(버금) + `--muted`, 투명도 금지. 모서리 `--r-md`. 내비 80 이상, 폰 주 56 · 버금 48.
- **고른 것**: `--primary-soft` 면 + 안쪽 2px `--primary-line` + `--primary-text` 700. 나눔 단추는 둥근 길(카드 안 `--surface-soft`, 바탕 위 `--canvas`) 안에서 이 면이 200 ms 미끄러진다. 3D 무대 위 나눔은 어두운 길 + 밝은 면(파랑 없음).
- **카드**: `--canvas` + `--r-lg` + `--e-0`, 테두리 없음. 누르는 카드는 누름 `--surface-soft`, 고름 = 안쪽 3px(폰 2px) `--primary-line`. 빨강 칸만 `--bad-soft` 면.
- **칸(계기 카드)**: 위 색 줄을 없앴다. 상태는 값 글자색 `--ct` + 막대색 `--c`. 막대는 6 px(폰 4) 둥근 길, 기준 눈금은 막대보다 키 큰 3×16(폰 2×12) `--ink`. 중립 값은 `--ink`, 막대 `--muted-soft`.
- **표지**: 둥근(`--r-md`) `--surface-dark` 칸 + `--c` 모양. 내비 80(모양 48) · 1080 92(56) · 시트 72(42), 폰 64(40) · 작은 띠 48(30) · 카드 44(26) · 잠금 112(64). 주행 색 기둥(§4.2)은 그대로 꽉 채운다.
- **줄**: 카드 안에서 줄 높이 내비 96 · 폰 56 ~ 72, 줄 사이는 들인 1px `--hairline`. 고른 줄 = 고른 것 규칙 + `--r-md`. 색 네모는 둥근 점(내비 20 · 16, 폰 10)으로, 뜻은 늘 옆 글이 전한다. 폰 줄 아이콘은 40 px `--surface-soft` 둥근 칸.
- **체크 칸 · 라디오 · 켜기**: 체크 = `--r-sm` 둥근 네모, 빈 칸 2.5px(폰 2) `--muted-soft` 테두리, 찬 칸 파랑 면 + 흰 ✓. 라디오 = 동그라미. 켜기 = 둥근 길(꺼짐 `--hairline-strong`, 켜짐 파랑) + 흰 동그란 손잡이.
- **증감**: `--surface-soft` 우물(폰은 흰 카드) 안에 둥근 단추 둘, 끝 값에서는 그쪽 단추가 면 없이 `--muted-soft`.
- **칩**: `--r-xs`. 상태 = `--c` 면 + `--on-status` 600, 중립 = `--surface-strong` + `--body`.
- **시트**: 내비 = 창에서 12 띄운 떠 있는 판(폭 640, 세로 창은 폭 가득), `--bg` 면 + `--r-xl` + `--e-2`. 머리(제목 36 + 동그란 닫기 80) → 카드 묶음(사이 12) → 맨 아래 주 단추. 폰 = 아래에서 올라오는 `--canvas` 판, 위 모서리 `--r-xl`, 손잡이 줄 36×4, 안의 고르는 줄은 `--surface-soft` 카드.
- **폰 뼈대**: 앱 바는 바탕 위(면 · 선 없음, 제목 20). 고정 영역과 탭 바는 아래에 붙은 한 장의 흰 판(위 모서리 20, 위로 옅은 그림자). 탭 고름 = 아이콘 뒤 옅은 파랑 알약 + 파랑 글. 토스트는 남색 면 + 흰 글.
- **내비 뼈대**: 판정 띠 · 막대 · 무대 · 칸 넷 · 오른 단이 각각 카드. 막대의 보기 셋은 나눔 단추(고른 것 규칙), 기록 · 설정은 조용한 단추. 화면 테두리(주행 빨강 8 · 주황 4, 다시 묶기 빨강 6 숨쉬기)는 각진 채로 창 가장자리 틈 위에 그린다.
- **3D 무대 안**(이름표 · 꼬리표 · 배지)은 `web/src/three/bed.css` 몫이라 이번에 손대지 않았다. 각진 채로 남아 있다.

| `--press-scale` | 0.97 (줄 · 카드 0.985) | 누름 |

3D (`web/src/three/bed-scene.ts`): 시점 바꿈 600 ms (들어가고 나오는 3차 곡선), 짐 밀림 1.2 s (3차 감속, 0.25 s 뒤 시작), 문제 벨트 숨쉬기 1.6 s 주기, 쉼 흔들림 ±5° · 20 s 주기 (손 뗀 뒤 5 s 부터, 2 s 에 걸쳐 들어옴).

**움직임 안전 규칙 (모든 판)**
1. 주행 중(앱 뿌리 `data-mode="drive"`, 폰은 운전 중 잠금)에는 CSS 애니메이션 · 전환 0 (`!important` 규칙), JS 움직임(숫자 세기 · 다 됐어요 · 3D 쉼 · 짐 밀림 · 벨트 숨쉬기)도 `motionOk()` 로 멈춘다. 확인: `motion-check.mjs` 의 `nav_7_drive` 줄이 "도는 움직임 0개 · 화면 같음".
2. `prefers-reduced-motion: reduce` 면 같은 규칙으로 모두 끈다.
3. 반복 움직임은 넷뿐: 다시 묶기 빨강 테두리 숨쉬기(정차), 듣는 중 목소리 막대(정차), 3D 문제 벨트 숨쉬기(정차), 3D 쉼 흔들림(정차, 손대지 않을 때). 기다림 빛 띠는 3D 장면을 진짜로 읽어 올 때만.
4. 상태 색 바뀜은 섞임(480 ms)만 하고, 깜박이거나 커지지 않는다. 주행 화면은 섞임도 없이 바로.

### 8.3 부품 규칙 (공용 — 끝냄: `tokens.css` · `ui/ui.css` · `ui/parts.tsx`)

- **S1 누름**: 모든 `<button>` 은 누르는 동안 `--press-scale` 로 작아지고(90 ms), 떼면 용수철로 돌아온다(150 ms). 사진: 없음, 프레임 `nav_9_check_0080ms`.
- **S2 주 단추**: 파랑 면 + 윗변 빛 1 px + 파랑 그림자(낮) / 검은 그림자(밤). 누르면 그림자가 없어진다. 사진: `p1224_park_slide_day.png` 의 '벨트 수 고치기'.
- **S3 고른 면**: 나눔 단추의 옅은 파랑 면은 320 ms 용수철로 옮겨 간다. 프레임: `nav_5_view_top_*`.
- **S4 상태 색**: `--c` · `--ct` 를 `@property` 색으로 등록해 판정이 바뀌면 판정 말 · 표지 · 칸 막대가 480 ms 에 걸쳐 섞인다.
- **S5 숫자 세기**: 칸의 숫자 값(`Tile`)은 처음 보일 때 0 에서 700 ms 에 걸쳐 센다 (`CountUp`). 버티는 제동은 `useRolled` 가 0 에서 굴러 온다. 시각 · 전화번호 · 말 값은 세지 않는다. 프레임: `nav_1_load_confirm_0200ms` 의 숫자가 마지막 값보다 작다.
- **S6 막대**: 칸 막대는 처음에 왼쪽에서 700 ms 에 차오른다. 기준 눈금은 막대보다 키 큰 3 × 16 선.
- **S7 체크**: 할 일 줄을 누르면 칸이 1.14 배로 튀고(320 ms) ✓ 가 그려진다(320 ms, 60 ms 뒤). 끝난 줄 제목은 `--body` 로 한 단계 낮아진다. 프레임: `nav_9_check_*`.
- **S8 듣는 중 알약**: 마이크 옆 목소리 막대 넷(6 × 36, 1.2 s 주기, 서로 0.3 s 어긋남). 주행 중에는 멈춘 높이(55 · 85 · 70 · 45 %)로 보인다.
- **S9 다 됐어요** (`celebrate()` · `<Celebrate/>`): '다시 조였어요' · '확인했어요' 뒤 1.8 s. 남색 동그라미 112(폰 88)에 흰 ✓ 가 그려지고 아래 한 줄 '다시 조인 것을 기록했습니다' / '확인한 것을 기록했습니다'. 초록(상태 색)을 쓰지 않는다. 프레임: `nav_10_relashed_0700ms`.
- **S10 나감** (`usePresence`): 시트 · 덮개는 닫을 때 200 ms 동안 나가는 움직임을 보인 뒤 사라진다.
- **S11 카드 마감**: 낮에는 칸 카드 윗변에 1 px 빛(흰 55 %). 밤에는 없음.
- **S12 기다림**: 3D 장면 덩어리를 읽어 오는 동안만 무대 색 위 빛 띠(1.4 s) + '불러오는 중'.

## 9. v4 디자인 방향 (2026-11-14, 아트 디렉터)

이 절은 §7 · §8 의 겉면 규칙 가운데 아래와 부딪치는 것을 대신한다. 기능 · 엔진 · 런타임 · 음성 문장 · 최소 크기(내비 실제 창 18 CSS px · 터치 61 CSS px · 대비 4.5:1) · 주행 규칙(움직임 0, 색 하나 + 한 줄) · Pretendard 하나 · 흰 판 금지 · 적재함만 보이는 3D 는 그대로다.

### 9.1 지금 무엇이 아마추어처럼 보이나 (솔직하게)

1. **색이 탁하다.** 낮 바탕 `#bcc7d3` · 카드 `#dce3eb` 는 채도 있는 회청(라벤더 기운) 이라 Pleos 시스템 크롬(무채색 밝은 회색 · 검은 선 아이콘, `shots/pleos_v3_land.png`)과 부딪치고, 옛 사무용 프로그램처럼 보인다. 그 위의 주황 글자 `#983c00` 는 갈색으로 읽혀 화면에서 가장 큰 글자("밀릴 수 있음")가 가장 지저분하다.
2. **센 곳이 없다.** 판정 띠 안에 표지 · 판정 말 · 세로 선 · 할 일 두 줄 · 주 단추 · 운송장 번호 두 줄이 같은 무게로 나란하다. 칸 넷 · 오른 단 · 막대도 모두 같은 카드, 같은 모서리, 같은 색이다. "카드를 늘어놓은 관리자 화면" 느낌.
3. **고른 것이 폼 입력처럼 보인다.** 옅은 파랑 면 + 2 px 파랑 테두리(막대 '3D', 짐 종류, 무게, 라쳇)는 포커스 테두리로 읽힌다. 파랑이 한 화면에 3 ~ 5 곳.
4. **3D 가 '어두운 상자 속 장난감'이다.** 낮 화면에서 남색 무대가 밝은 판에 박힌 검은 사각형이 되어(사용자가 말한 "흰 틀") 3D 가 떠 있다. 바닥 그림자가 남색에 묻혀 적재함이 공중에 뜬다. 보통 벨트가 흰 반투명 띠라 유령처럼 보이고, 무대 위 이름표(3D 디지털 트윈 · PV5 오픈베드 / 앞 · 운전석 쪽 / + 여기에 바 하나 더)가 서로 다른 모양으로 세 개 떠 있다. 실사 렌더(`IsaacTwin/sim_real_truck/results/hero/hero_bed.png`)의 은색 알루미늄 · 어두운 바닥 · 부드러운 그림자와 거리가 멀다.
5. **표지가 앱 아이콘처럼 보인다.** 남색 둥근 네모 안의 경고 모양(내비 · 폰 · 잠금 화면)은 경고등이 아니라 앱 아이콘이다.
6. **빈 곳이 많다.** 주행 화면은 왼쪽 1/3 주황 기둥 + 왼쪽 정렬 한 줄이라 오른쪽 2/3 이 비어 '덜 만든 화면'처럼 보인다. 오른 단 '눈으로 확인' 아래 절반이 비어 있고, 기록 화면 왼쪽 목록은 한 줄에 화면 1/3 을 쓴다. 폰 잠금 화면도 회청색 빈 판.
7. **폰 허브 상태 칩이 사탕 색이다.** 빨강 · 주황 · 초록 꽉 찬 알약이 줄마다 있어 무엇이 급한지 오히려 안 보인다.
8. **시연 무대가 개발 도구처럼 보인다.** 1920 내비가 화면 절반 폭으로 작게, 폰이 옆에, 시연 패널이 오른쪽에 같은 무게로 놓였다.

### 9.2 방향 한 줄: "Graphite & Fog — 차에 원래 있던 기능처럼"

현대 · 기아 ccNC 와 Polestar · Rivian 차 화면이 공통으로 지키는 원칙만 가져온다: **무채색 면 위에 색은 상태 하나와 주 단추 하나**, **글자 크기와 굵기로만 위계**, **차는 바닥 위에 놓인 실물처럼**, **조용하고 정확한 움직임**. Toss · Linear 에서는 '한 화면 한 주 단추', '고른 것은 진한 면', '선 대신 간격'을 가져온다. 남의 그림 · 글 · 로고 · 아이콘은 쓰지 않는다.

- **면**: 낮 = 'Fog'(차가운 기운이 아주 조금 있는 무채색 연회색, 흰색 아님), 밤 = 'Graphite'(푸른 기 없는 흑연색). 회청 · 남색 계열을 버린다.
- **3D 무대에 틀이 없다**: 무대 배경 = 앱 바탕과 이어지는 '스튜디오 바닥'. 낮에는 밝은 바닥, 밤에는 어두운 바닥. 적재함이 그림자를 드리우고 그 위에 놓인다. 어두운 사각형이 사라지므로 "흰 틀" 문제가 뿌리부터 없어진다.
- **색의 역할 셋뿐**: ① 상태 색(초록 · 주황 · 빨강 · 회색) = 경고등과 3D 문제 벨트, ② 파랑 = 화면당 주 단추 하나, ③ 나머지 전부 흑연 · 안개 단계. 판정 말 · 칸 값은 **잉크색**으로 쓰고 상태는 경고등 · 막대 · 점이 전한다.
- **고른 것 = 진한 면**: 낮은 흑연 면 + 흰 글, 밤은 밝은 면 + 흑연 글. 파랑 테두리 금지.
- **경고등(telltale)**: 표지를 '상태 색으로 꽉 찬 둥근 네모 + 흑연 모양'으로 바꾼다. 계기판 경고등처럼 읽힌다. 화면에서 가장 센 점은 이것 하나.
- **글자**: Pretendard 하나, 굵기 400 · 500 · 600 · 700 만, 숫자는 `font-variant-numeric: tabular-nums`, 단위는 값의 0.45 배 `--muted`.
- **대표 화면은 밤**: 기획서 · 영상의 첫 그림은 밤 테마(차 화면은 어두운 쪽이 실제 제품처럼 보인다). 낮도 같은 완성도로 맞춘다.

### 10.2 방향 한 줄: "Obsidian Studio — 검은 스튜디오 위의 적재함"

자동차 컨피규레이터처럼 **검은 스튜디오 바닥 위에 적재함 하나만** 올려 두고, 앱 화면은 그 둘레에 **어두운 면의 밝기 차이만으로** 정리한다. 흰색 · 밝은 회색 면은 어디에도 쓰지 않는다(카드 · 시트 · 알림 · 토스트 · 창 테두리 · 무대 둘레 · 기기 틀 모두). 밝은 것은 글자, 상태 색, 주 단추 하나, 3D 속 금속 반사뿐이다.

원칙 다섯:
1. **검정은 한 가지 바탕**: 앱 바탕 = 3D 무대 바탕 = Pleos 아래 독 막대와 같은 거의 검정. 무대와 바탕 사이에 경계선이 없다.
2. **면은 세 단계만**: 바탕 < 카드 < 우물 · 버금 단추. 선 대신 밝기 차이로 나눈다. 밝은 1px 선 금지.
3. **화면당 메시지 하나**: 같은 문장을 한 화면에 두 번 쓰지 않는다. 판정 · 할 일 · 주 단추가 한 덩어리.
4. **숫자는 주인공이 아니다**: 판정 말 > 할 일 > 칸 값 순서로 크기를 확실히 나눈다.
5. **3D 는 화려하게, 판은 조용하게**: 빛 · 반사 · 재질은 3D 에만 쓰고, 판에는 그림자 · 그라데이션 · 빛 번짐을 쓰지 않는다.

### 10.7 하지 말 것 (다크 프리미엄)

- 흰색 · 밝은 회색 면(카드 · 시트 · 알림 · 토스트 · 기기 틀 · 무대 둘레), 밝은 1px 테두리.
- 3D 를 카드 · 사각형 안에 넣기, 트럭 운전석 · 바퀴 · 도로가 보이는 그림.
- 같은 문장을 한 화면에 두 번 이상, 알림에 꺾쇠 · 머리 줄 · × 를 모두 넣기.
- 판에 빛 번짐 · 네온 · 그라데이션 · 유리 흐림(화려함은 3D 에만).
- 칸 값을 판정 말만큼 크게, 보조 설명 두 줄 이상.
- 다른 제품의 그림 · 아이콘 · 로고 · 글 가져오기.
